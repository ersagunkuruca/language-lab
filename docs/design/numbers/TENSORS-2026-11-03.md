# Tensors (L51)

Design note, 2026-11-03. BACKLOG L51, NUMBERS.md stage 6 ("Vectors,
matrices and tensors"). It doesn't wait on C30 any more: `array of List`
is a representation written in the language and chosen on every engine,
and what is left of C30 is speed.

## What a tensor means

A tensor means a **shape** and a **function from an index to an item**,
as NUMBERS.md says. The shape is a list of axis lengths, `[2, 3]` for a
2 × 3 matrix, `[]` for a single number. An index is a list of positions,
one per axis, each from 0 up to the axis's length.

Two tensors are equal when their shapes are equal and every index gives
equal items. So `transposed` means swapping the index and costs nothing.
Whether it costs anything when the program runs is up to the
representation.

## What it is in the language

```
Tensor a = tensor(shape: List Int, items: List a)
```

The items are listed with the last axis changing fastest (row-major, as
in NumPy and C). That order is how a tensor is written down and taken
apart, not how it has to be stored. A list of items is stored as an array
wherever `array of List` pays (C30d), so `entry` is a lookup there. A
strided, diagonal, sparse or broadcast store would be another
representation of the same meaning (NUMBERS.md), chosen by the compiler.
Those are C rows, and none is needed for a first program.

The constructor is private. A tensor is made by `tensor of(shape,
items)`, which stops when the item count isn't the product of the shape,
and says both numbers. Its parts are read with `shape` and `items`.

## One operation, and the rest call it

The library is one operation plus conveniences, not forty special
functions (NUMBERS.md):

- **`contracted(a, b, pairs)`**: the product of `a` and `b` summed over
  each pair of axes `(i of a, j of b)` in `pairs`, which must have equal
  lengths. The axes left over, `a`'s then `b`'s, are the result's.
  This is Einstein summation over named pairs. Matrix product is
  `contracted(a, b, [(1, 0)])`, a dot product `contracted(u, v, [(0,
  0)])`, the outer product `contracted(a, b, [])`, and a matrix times a
  vector `contracted(m, v, [(1, 0)])`.
- **`tensor map(f, t)`** and **`tensor zip with(f, a, b)`**: item by item.
  Zipping stops when the shapes differ, and says both.
- **`transposed by(t, order)`**: axis `order[k]` of `t` becomes axis `k`.
- **`reshaped(t, shape)`**: the same items, read with another shape of
  the same size.
- **`traced(t, i, j)`**: the sum over the diagonal of axes `i` and `j`.
- **`entry(t, index)`**, **`rank(t)`**, **`tensor size(t)`**.

`contracted` takes Number items: `+` and `·` are the one generic
arithmetic, so it works on Int, Float64, Rational, Complex and Fixed
tensors alike.

## Arithmetic

A Tensor of a Number has an Arithmetic: `+`, `−` and `−x` item by item,
and `·` item by item too (NumPy's `*`). The shapes must match. A mismatch
stops the program and says both shapes, as Matrix does. Matrix product is
`contracted`, not `·`. A program that wants `·` to be the matrix product
uses `Matrix`, whose `·` already is.

`·` is item by item because that is the only product every shape has.
Matrix product needs exactly two axes, and a tensor's rank isn't in its
type yet.

## Shapes in types: not yet

NUMBERS.md wants shapes inferred, with each axis length an unknown and
the operations giving linear equations between them, as units.ts solves
dimensions. That needs numbers in types, which the language doesn't have
yet. Until then a shape mismatch is a stop that names both shapes. This
is the same choice Matrix made (MATRICES.md layer 3). A later row moves
the check into the checker. Nothing written against this design changes
meaning then: a program that ran keeps its answers, and one that stopped
on a mismatch becomes a type error instead.

## Matrix

`Matrix a` (L44) stays. Later it can be the rank-2 view of a tensor, with
ids kept for saved programs (L184). It isn't folded into Tensor now,
because Matrix's `·` is the matrix product and Tensor's is item by item.

## Steps (row L51)

- **(a)** The type and its constructor, `tensor of`, `shape`, `items`,
  `entry`, `rank`, `tensor size`, `tensor map`, `tensor zip with` and
  `reshaped`, written in the language (prelude), each in LIBRARY.md.
- **(b)** `contracted`, `transposed by` and `traced`, with matrix product,
  dot and outer product checked against Matrix's.
- **(c)** The Arithmetic implementation.
- **(d)** A bigger program that needs a tensor bigger than a 4 × 4 matrix,
  such as a small neural network layer or a heat diffusion stencil. NUMBERS
  stage 6's trigger is "a numeric example needs a matrix bigger than
  3 × 3".
- **Later:** strided, diagonal and sparse representations (C rows), and
  shapes in types.

## Credits (prior art)

- NumPy's ndarray for the shape and row-major order, and `numpy.einsum`
  for contraction over named axes. Einstein's summation convention is
  behind both.
- APL and J for treating arrays of any rank as one kind of value, with
  operations lifted item by item.
- Dex (Paszke et al., 2021) and Futhark for array programs whose shapes the
  checker knows. That is the direction for "shapes in types".
- BLAS for the operations a contraction has to make fast. That is the
  compiler's job, not the meaning's.
