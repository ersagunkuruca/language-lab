## The idea

A grammar is a list of rules, each a list of symbols rewritten to another:

```
type Symbol = terminal(t: Text) | variable(v: Text)
type Rule = rule(left: List Symbol, right: List Symbol)
type Grammar = grammar(start: Text, rules: List Rule)
type Level = regular | context free | context sensitive | unrestricted
```

`level of(g)` is the narrowest level every rule fits (right-linear,
one variable on the left, no rule shorter on the right than on the left,
anything). A machine for each level is a value too: a finite automaton
(edges on symbols), a pushdown automaton (edges that pop and push), and a
Turing machine (a table from state and symbol to state, symbol and move),
of which a linear bounded automaton is one that never leaves its input.

Three things Ters has make this more than a textbook in code:

1. **Nondeterminism is Choice.** A derivation step is `one of` the rules
   and `one of` the places where its left side occurs. An NFA's move, a
   PDA's move and a nondeterministic Turing machine's move are the same.
   `first` answers "is the word in the language", `all` gives every
   derivation, `count` how many: `count` of a context-free grammar's parse
   trees for a word is its ambiguity on that word, with no extra code.
2. **The level shows in the effects.** The checker infers `Diverge` where
   it can't see a recursion end, and `with fuel(n, …)` turns `Diverge`
   into `Choice` (LANGUAGE.md "Loops"). Recognising a word of a regular,
   context-free or context-sensitive grammar can be written so it ends
   (a fold over the word; a search whose forms never grow past the word,
   for a grammar whose rules never shrink); recognising a word of an
   unrestricted grammar can't, and a Turing machine's run is `Diverge`.
   The aim is that the hierarchy's line between decidable and
   semi-decidable is the line between a type without `Diverge` and one
   with it, so the checker states the theorem. Where it doesn't (a
   bound the checker can't see), that is a finding.
3. **Relations run both ways.** A parse tree's yield is a fold that
   prints; run backwards it parses. Whether `inverse` of a grammar given
   as data reads words (the relational search) and how it does against the
   machine built for the same grammar is part of the exploration.

## Findings (L293f, 2026-11-27)

What L293a to L293d showed, with the example as built (`examples/chomsky`,
94 definitions, written through the MCP's tools; driver in project files
under `chomsky/`).

**The thesis holds.** Every recogniser below the unrestricted level is
total in its type, and only the two searches with no bound carry
`Diverge`: the unrestricted grammar's derivation search (`searched`) and a
Turing machine's run (`ran`). Each is run under `with fuel`, so `main` is
`(List Text) -[Console]-> Unit`. The bounds that make the others total are
the textbook's own arguments, written as counts the checker reads: the
number of forms no longer than the word (a grammar that never shrinks),
2ᵏ sets of states (the subset construction), a stack no longer than what
is left of the word (a pushdown automaton of such a grammar), and a linear
bounded automaton's number of configurations.

**Choice is the nondeterminism, at every level.** A derivation step, an
automaton's move, a pushdown automaton's move are each `one of`; `count`
of a pushdown automaton's runs is the number of parse trees (a+a+a+a: 5
in E → E+E \| E*E \| a, 1 with precedence), with no ambiguity code.

**Gaps the example wrote around:**

1. **A parameter's type can't be written in text** (L296). A count down
   (`rounds − 1` guarded by `rounds ≤ 0`) stays a generic number when
   nothing else in the body is Int-only, and the counting check (L46)
   only counts an Int, so the definition is `Diverge`. The driver writes
   a use only an Int has (`quotient(rounds, 1) < 0`) so the literals
   settle, then deletes it, four times. The same cause made `m.start`
   take the wrong record type when two types have a `start` field
   (Automaton's became `initial`). Built 2026-11-28: a pin written in
   text (`pin` with a `type`) types a function's inputs in its body.
2. **`with fuel` slows down step by step when the call is in a match
   arm** (L295). `spin2(x) = if x = −1 then true else match first
   where([1], …) none → spin2(x + 1) …` under `with fuel`: 1,000 steps
   1.1 s, 4,000 steps 6.5 s; the same loop written with `if` alone 0.6
   and 1.4 s. The Turing machine's run hit it: 1,000 steps 5 s, 2,000
   steps 19 s, where the same run counted by hand, no fuel, does 10,000
   in 0.4 s.
3. **Text reading, small** (L297): a type of two words in a field's type
   needs brackets (`List (Push move)`; `List Push move` reads as a type
   `Push`); steps inside a fold's or match's arm weren't found to read
   (`(k = …; □ …)`), so a helper took their place.

**Not built, and why.** L293e (a PDA to a grammar, a Turing machine to an
unrestricted grammar) would add two long constructions without a new
idea about the language: the checks they need are the same words-up-to
comparisons already made. Declined by Ersagun 2026-11-28.

## Prior art

- **The hierarchy itself**: Noam Chomsky, "Three models for the
  description of language" (IRE Transactions on Information Theory, 1956)
  and "On certain formal properties of grammars" (1959). Prior art.
- **Linear bounded automata and context-sensitive languages**: S.-Y.
  Kuroda, "Classes of languages and linear-bounded automata" (1964).
  Prior art.
- **JFLAP** (Susan H. Rodger and others, Duke University): grammars and
  automata as objects you convert between and test against each other.
  Influence on which conversions and checks the example has.
- The textbook constructions (Thompson's, the subset construction, the
  grammar-to-PDA construction) are common knowledge and not credited one
  by one; scan credits the ones it adapted.
