# Grammars written once, as printers

Design note for BACKLOG L70, from
[LANGUAGE-NEEDS-2026-10-24](../../reports/reviews/LANGUAGE-NEEDS-2026-10-24.md)
§8. Written 2026-11-02 by the Language lane, after L172 made `joined`
run backwards as `split`. Nothing here is built yet; the steps at the end
are the rows.

## The problem

calc reads a line in two passes. `tokens` cuts the text into numbers,
words, symbols and gaps. Then eight definitions (`expression`, `sum`,
`sum rest`, `product`, `product rest`, `unary`, `power`, `atom`) parse the
tokens by recursive descent. Each of the eight returns a `Parsed` (the
expression and the tokens left) and has `Diverge` and `Abort`. Its printer,
`parenthesized`, is one fold of four arms.

The grammar is said twice: once in `parenthesized`, and once, in another
shape, in the eight parsers. A change to the syntax, say `^` binding
tighter than unary minus, is made in both or the two drift apart. board
and machine have the same pair, smaller: `card line` with `read card`, and
`disassembled` with `instruction of` (REVIEW-2026-11-02d §4).

The language already runs a function backwards (`inverse`, MODES.md). Since
L172, `inverse(card line, text)` reads a card wherever no field holds the
separator. So a printer with one way to print each value is already a
parser. What's missing is a printer that a whole grammar can be written as.

## What a printer has to say

`parenthesized` can't be run backwards as calc's parser for three reasons,
and each is a thing the grammar knows that the printer doesn't say:

1. **Where parentheses are optional.** `parenthesized` puts them around
   everything, so it reads only fully parenthesized text. A grammar says
   that `1 + 2 * 3` needs none: a level's parentheses are optional exactly
   when the inner operator binds tighter than the outer one.
2. **Where spaces are optional.** `"(" ++ a ++ " " ++ op ++ …` prints one
   space. Read backwards, that means only one space is accepted.
3. **Which of several texts is the one printed.** Backwards, every
   accepted spelling must give the same value; forwards, one spelling is
   chosen. `show(n)` already works like this: `inverse(show, "12")` is 12,
   and printing 12 gives "12".

So the note proposes no parser combinators. It proposes a few printer
pieces, each with a forward direction (print one way) and a backward
direction (accept several). They are ordinary prelude definitions over
`Text`, written in the language, and each one is checked to run backwards
(modes.ts) the way `joined` now is:

| piece | forwards | backwards |
|---|---|---|
| `spaced(t)` | `t` | `t` with any spaces around it |
| `optional parens(needed, t)` | `"(" ++ t ++ ")"` when `needed`, else `t` | `t` or `"(" ++ t ++ ")"`, whichever parses |
| `joined(parts, sep)` (L172) | the parts with `sep` between | the text split at `sep` |
| `show(n)` / `read whole number` | the digits | the digits |

With these, calc's grammar is one fold. A level knows its own binding
strength, and each child is printed with parentheses only when the child
binds more loosely:

```
expression text(e, outer) = fold e
  literal(v) → show(v)
  variable(n) → n
  negative(x) → optional parens(outer > unary, "-" ++ x(unary))
  binary(op, l, r) → optional parens(outer > strength(op),
                       l(strength(op)) ++ spaced(op) ++ r(strength(op) + right side(op)))
```

`inverse((e) ↦ expression text(e, 0), line)` is then the parser. The fold
is structural, so forwards it ends. Backwards, each piece consumes at
least one character or ends on a known one, so the search ends too (the
sizes argument MODES.md uses for `concat`). One more thing makes the
answer unique: `right side(op)` puts `a - b - c` to the left and `2 ^ 3 ^ 2`
to the right.

## How it runs

Run backwards by the relational interpreter, the parser is a search. It
tries each arm of the fold against the text, and that is exponential in
the worst case. Two things keep it practical:

- **Tokens first.** `tokens` stays as it is (or becomes `split` on
  boundaries), and the grammar reads a list of tokens instead of
  characters. The pieces above are then the same over `List Token`.
  Backwards, each step consumes one token and the branching is per token.
- **A compiled parser.** COMPILER.md ("Relations: the solver is the
  compiler") plans a static mode analysis in Mercury's style: a direction
  whose calls can be ordered ahead of time compiles like a forward
  function. A grammar whose levels are told apart by their next token
  (LL(1)) has such a direction, so it would compile to recursive descent:
  the eight definitions calc writes by hand, generated. A grammar that
  isn't LL(1) still runs, as a search.

Errors need one addition. A backward run with no answer says only that no
expression was found. calc prints where the text stopped making sense.
The relational interpreter knows the furthest position any branch
reached, which is the "expected … at" message every parser generator
gives. That is a small change to `inverse`'s refusal.

## Steps

1. **L70a:** the two pieces `spaced` and `optional parens` in the prelude,
   each with its backward mode checked to end and to give one answer, and
   tests run both ways (S).
2. **L70b:** calc's grammar as `expression text`, beside its hand parser.
   The calc test compares the two on calc.ts's random sessions, and the
   benchmark shows the evaluator's cost (M).
3. **L70c:** where the backward run stopped, as `inverse`'s message (S).
4. **C lane:** an LL(1) backward mode compiled as recursive descent, then
   calc's eight parsers deleted (M; part of COMPILER.md's mode analysis).

board's `read card` and machine's `instruction of` become `inverse` of
their printers once step 1 is in. Each of their fields is a `show` or a
known word, and L172 handles the separators.

## Prior art

- **Invertible syntax descriptions** (Tillmann Rendel and Klaus Ostermann,
  Haskell Symposium 2010): one description gives a parser and a pretty
  printer, built from partial isomorphisms. The pieces above are that
  idea, with the language's own `inverse` as the isomorphism machinery.
- **Boomerang** (Aaron Bohannon, J. Nathan Foster, Benjamin Pierce,
  Alexandre Pilkiewicz, Alan Schmitt, POPL 2008): bidirectional string
  transformations whose backward direction chooses a canonical value, as
  `optional parens` chooses to print the fewest.
- **Precedence climbing** (Keith Clarke, 1986; Pratt's top-down operator
  precedence, POPL 1973): a level's binding strength decides its
  parentheses. That is how `expression text` passes `outer` down.
- **Prolog's DCGs:** a grammar run as a relation, both directions, by
  search. Here the search is the relational interpreter's, and
  determinism decides when it compiles to a loop.
