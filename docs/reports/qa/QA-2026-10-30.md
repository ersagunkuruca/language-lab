## Smoke

`npm run smoke`, now 20 definitions after #636 and #640, fails on `main` on one check. It failed twice, the second time run on its own (6 minutes): "a value added on the canvas: no Add a value on the canvas". In a fresh browser the same gesture works: Numbers & physics → `fall` → right-click the canvas's bottom-right corner offers Add a value here… (`fall-canvas-menu.png`). So it's likely state left by an earlier check in the same browser, since pages share localStorage, rather than an editor bug. See M2. The first run, alongside this pass's scripts, also failed the "run backwards, first answer first" timing check. That check passed when the smoke ran on its own.

Per Ersagun's note of 2026-10-29 on the browser smoke, later passes will run only the checks they need, not the whole smoke.

## Suggested order

One PR each:

1. M1: a page that's the run gets room, or starts scrolled to what to play with.
2. M2: the smoke's "value added on the canvas" check opens its own fresh context, or the smoke's replacement covers it.
3. L1: a page's `main` opens on its tree, not on the right edge.
4. L2: a result still being searched reads "searching", not `[]`.
5. L3.

## How to repeat

As in [QA-2026-10-29.md](QA-2026-10-29.md). New this time:

- **Embeds:** open `index.html?embed&program=<program>&def=<definition>`, adding `&readonly` if wanted, in an 800×760 page. Example programs are named as in the tutorial: `sort`, `dice`.
- **A page's height:** `.side iframe` → `contentDocument.documentElement.scrollHeight`.
- Run the smoke on its own. With other browser scripts running at the same time, its timing checks are less reliable.
