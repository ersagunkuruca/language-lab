# Editor click-through QA, 2026-10-23

The second point-and-click pass over the editor, a day after [QA-2026-10-22.md](QA-2026-10-22.md). About 40 commits touched the editor since then: effects in the editor, value definitions that run, the shader examples in the program list with a live picture, Run at the top, the guide as a tab, deselect, new things panning into view, and more. Every example program and definition was opened, run and shown in all four text views. Then the gestures were tried again: filling holes, adding inputs and definitions (function, value, effect), renaming, wires and dots, inline, the right-click menus, undo, save and open, search, the side pages, keyboard and phone width.

**Build tested:** the committed `index.html` at `cb1f4dd` (main this morning), opened from disk with headless Chromium through playwright-core. A fresh `npm run build-editor` gave the same file. `npm run smoke` passes (102 definitions, and 16 more on programs saved by an older editor). There is no GPU in the container, so the shader previews ran on the CPU fallback (WebAssembly).

Screenshots are in [qa/2026-10-23/](screenshots/2026-10-23/).

## Things that can't be edited from the editor

Yesterday's list, re-checked. Item 1 (effects) is done. The rest still holds:

1. **Inner lambda parameters** can be renamed, but not added, removed or reordered.
2. **Swapping a call's function while keeping its arguments** (`+` → `·`). The node menu offers Open, Show inline, Put a dot, Clear, Back to the automatic place, Tidy, Reset and Fit, but no Replace.
3. **Statement order in an action** (`print` steps in `main`).
4. **Data type field types** beyond the offered list.
5. **A used input can't be removed directly.** `Delete fall` and the input's × are disabled while it's used.
6. **The palette on an `a` hole** lists 211 entries and starts with `for each`, `map`, `keep`. A new `main` has no "print first" ordering. Search narrows it well (`print` finds `print(□)` first). `√` still finds nothing, because the function is called `sqrt`. `1 + 2` isn't understood.

## UX issues (ranked)

1. **Most functions open in a warning state.** (Was UX 3, unchanged.) 79 of 102 definitions open with an orange "Give x a value, or untick it" and no values on the wires. That includes every shader function, every derivative and every Calculus function except `zeros of …` and `samples`. It's the most common first impression of a definition. It could be seeded from how `main` (or the picture's x, y, time) calls it, or worded and coloured as a neutral prompt.
2. **Tabs pile up.** (Was UX 7, unchanged.) Opening 10 definitions makes 10 tabs. The strip runs off the right edge with no overflow control, and the graph hint is pushed out (`tabs-pile-up.png`).
3. **Show inline overflows.** (Half of UX 5.) Inlining `discriminant` in `root` grows the graph past the right edge with no refit, and the result is cut off (`inline-overflows.png`). Its parameter labels sit on wires.
4. **Big graphs open partly off-screen.** Large graphs now open at 60%. Only 36% of Numbers & physics `main`, 37% of `shade`, 51% of Run backwards `main` and 57% of the `∂shapes` derivatives is on screen at first (`main-at-readable-zoom.png`). That's a fair trade, but there's no minimap or "there's more" cue. The Fit / 100% pill also covers nodes in the bottom-left corner.
5. **The zoom level isn't shown.** (Was UX 8.) The "100%" button means "Actual size" and still reads 100% at 60% or 44%. A plain mouse wheel zooms.
6. **A program opens on whichever definition was last open,** or its first one, not on `main`. (Was UX 9.) Eight queens opens on `queens`.
7. **Keyboard.** (Was UX 13.) Tab reaches the toolbar, the navigator, the graph's tabs, Fit, the view switch, the Text pane, the Run inputs and the inspector tabs, but no node, port or hole. Every edit still needs a mouse.
8. **Phone width (390 px).** (Was UX 14, unchanged.) The panes stack into a 3,100 px page, and the graph sits in the bottom-left of its pane (`phone-390.png`).
9. **Unit refusals don't name the units.** "Refused: units don't agree here." could say "speed is m/s, gravity is m/s²".

## How to repeat

The same setup as yesterday: `npm run build-editor`, then playwright-core with `executablePath: "/opt/pw-browsers/chromium"` on `file://…/index.html`. Useful selectors: `[data-set="program"]`, `[data-def]`, `[data-panel=node|program|checks|files|guide]`, `[data-act]`, `.ctx-item[data-menu]`, `#nav-find`, `.side input[type=search]` (the palette). Graph nodes are `.p-graph g.items > g` with a `rect[data-move]`. Input ports are `circle.inp[data-slot]`, wires are `path.edge-hit` and `path.use-hit`, and the label text is SVG, so read it with `textContent`, not `innerText`. With Playwright's `getByRole`, pass `exact: true` for "Value", because "Show values" also matches.
