# Editor click-through QA, 2026-11-02

QA14. It follows [QA-2026-11-01b.md](QA-2026-11-01b.md) (QA13). It was started to refill the Editor lane, and it looks at what bigger-program round 7 (the sheet, GAPS.md) changed in the editor, #979 to #1004:

- **Typing in the palette:** read once after a pause (E173, #979), with the list following each key (E173b, #986).
- **Refusals that say why** (E174, #981), with *Let it loosen* beside a fill the held type refuses (E179, #996) and *Make a definition named X* beside a call of a name nothing has (E180, #997).
- **Which meaning a typed name takes:** open types left open (E175, #983; E175b, #994), meanings narrowed by the types around them (E176, #988), the program's own definition marked (E182, #999), print listed once (E184, #1001).
- **What typed text can write** (E178, #991): `else`, lists of expressions, steps, holes.
- **A fresh match** reads a row and a hole per case (E177, #987).
- **Make it a value / Make it an action** for a definition with no inputs (E181, #998).
- **A filled step nothing reads** reads as the step (E183, #1002), and **↑ what it's in** / Alt+↑ (E183b, #1004).

**Build tested:** `main` at `1cb77ae` (#1004), built with `npm run build-editor` and opened from disk in headless Chromium (playwright-core), since the live page can't be reached from here. There's no GPU, so the shaders ran on the CPU fallback. Following Ersagun's note of 2026-10-29, the full smoke wasn't run.

Screenshots are in [screenshots/2026-11-02/](screenshots/2026-11-02/).

## What works

- **Every example's `main`, and every definition.** All 22 programs were opened, every definition of each, with no page or console error. Every text `main` printed what it should (physics, sort, queens, Countdown, calculus, Run backwards, conjugation, relations, effects, Lockstep). All nine page programs drew their page in the Run panel, and the three shaders drew on the CPU. No definition's side panel showed an internal error, a raw hash, or "the search found no result". Three definitions took over 800 ms to open: bounce's `geometric product` (1.2 s) and `moved` (0.84 s), and Spacetime's `rapidity picture` (1.1 s), about as in QA13.
- **QA13's findings hold fixed.** Ray marching's helpers show values, not a JavaScript error. Pig's and bounce's helpers open without a failed search. A node's menu shows in about 0.1 s (physics `fall`'s `+`: 95 ms, was 0.45 to 0.75 s). After Make it a function the text reads `part(drift, drop)`, and the graph and the text agree.
- **E180, Make a definition named X.** In a new program, `helper(3, 4)` typed into `main`'s hole is refused with "there's no function named helper" and the button beside it. Its click makes `helper(input 1, input 2) = □`, keeps the typed text, and Enter then fills `main() = helper(3, 4)` (`e180-made.png`). The same works at phone width (`phone-refused.png`).
- **E174, refusals say why.** In `fall`, with `0.5` cleared: `"half"` gives "multiply needs Float64 here, got Text". `speed / 2` gives "units don't agree here: drift is m, drop is m²/s", which is exactly right. `nosuch(2)` names the missing function.
- **E179, a held type.** In two dice's `a hundred rolls`, with `seed` cleared, `die()` is refused in the held type's own words ("it would do Random where a hundred rolls doesn't"), with *Let it loosen* beside it. After *Let it loosen*, `die()` fills, and the type becomes `(a) -[Random]-> List Float64` (`e179-die.png`).
- **E175, E176, E182, E184.** `show(n)` in a new `f(n)` leaves `n` open: `f : (a) -> Text`. `length(xs)` takes List's length: `(List a) -> Int`. With a definition named `length` of the program's own, the palette lists it as "this program's own" between the library's two (`e182-length.png`). `print` is one row.
- **E178, typed text.** `[show(1), "a"]`, `a = 3; a + a`, `□ + 1`, `first(1, else 2)`, `if 1 < 2 then "a" else "b"`, `(x) => x + 1` and `length([1,2]) + 1` all read. Enter pressed before the pause reads first, then fills (`1 / 4` in `fall`).
- **E177, a fresh match.** On a data type with two cases, *match s · Shape* reads `circle → □` and `square → □` in the text, one hole per case. Filling the first selects the next hole, with the palette's box focused (`e177-match.png`).
- **E181.** A function made with no inputs and filled with `[1, 2, 3]` offers *Make it a value*, which turns `symbols() = [1, 2, 3]` into `symbols = [1, 2, 3]`.
- **E183.** *Add a value before this…* on physics `main`'s first print, filled with `print("x")`, reads as the step `print("x")`, with no `‹•1› =`. Adding cases to a data type keeps the New case field focused.
- **The palette's box is emptied** when another definition opens.

## How to repeat

As in [QA-2026-11-01b.md](QA-2026-11-01b.md). New this time:

- **Typing:** fill `#f-query` with `pressSequentially(text, { delay: 40 })`, then wait until `.side .palette` no longer says "Reading what's typed…". For a key's cost, `keyboard.type` one character, then wait for `requestAnimationFrame` and a `setTimeout(0)`, and time the two.
- **A new definition:** `[data-act="new-def"]`, then `#f-def-name` and `#f-def-inputs` (or `#f-def-case` for a data type), then Enter. Data type cases are added in `#f-new-case`.
- **A refusal's buttons:** `.side .palette button` with "Make a definition named" or "Let it loosen".
- **↑ what it's in:** the button is in `.side .insp-head`; after Alt+↑, read the panel's kind there too, since the blocks don't always mark what's selected.
