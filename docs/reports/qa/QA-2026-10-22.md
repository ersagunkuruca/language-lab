# Editor click-through QA, 2026-10-22

A point-and-click pass over the editor: every example program and definition was opened, run and shown in all four text views, then edited with every gesture the Guide and the menus offer. The pass used headless Chromium (playwright-core) driving the page like a user would: clicks, drags, right-clicks, typing and keyboard shortcuts.

**Build tested:** the committed `index.html` at `3a5683b` (what Pages served at the start of the run). The live URL couldn't be reached from the test container, so the committed build was opened from disk. PR #60 (effects in the editor) and PR #64 (polar from x and y) merged during the run. The top findings were re-checked on `770a080`: the polar bug is fixed there, and everything else below still happens. Effects editing from #60 was **not** tested.

Screenshots are in [qa/2026-10-22/](screenshots/2026-10-22/).

## What works well

Most of the editor holds up. None of these gestures threw a page error or console error in any of these runs:

- All 55 definitions across the 6 examples open, draw and run. All four text views render. No node overlaps were found after layout.
- Filling holes from the palette works, including typed values (`3`, `42`). Holes come back after Delete, Clear, or dragging a wire into empty space.
- Wiring a parameter dot onto a hole by drag works. So does clicking a wire to add a dot, naming the dot, and removing it.
- Inputs can be added, reordered and removed, and every call stays in step ("1 call swapped their arguments to match").
- New functions, values and data types can be created, and cases and fields can be added.
- `match` from the palette turns into an `if` for Bool.
- Save file, Open file, persistence across reload, Reset of an example, and the right-click menus (space, node, binder) all work.
- Show inline and let/get nodes work.
- Undo and redo work, including Ctrl+Z and Ctrl+Shift+Z.
- Refusals explain themselves ("multiply needs Number here, got (Number) -> Number").

## Things that can't be edited from the editor

These were looked for and no gesture was found. Text views are read-only by design, so they're not listed.

1. **Effects and handlers** (declaring `-[Console]->`, writing a handler). This was out of reach at `3a5683b`. PR #60 adds it, and it was **not** tested here.
2. **Inner lambda parameters.** A frame's `(head, tail, tail′) =>`, a `for each` body `(board) =>`, or a `for some` binder can be renamed, but not added, removed or reordered. Only top-level definitions have an Inputs list.
3. **Swapping the function of a call while keeping its arguments** (`+` → `·`, `first` → `all`). Clear to a hole throws the arguments away. Today the only way is to copy each argument, clear, refill, and paste them back.
4. **Statement order in an action.** The `print` steps of `main` can't be moved up or down.
5. **Data type parameters and field types.** The field type list offers Number, Text, Bool, Unit, Abort, Log, the type itself, and `List` of each. Int, function types, `List (List …)` and type variables are missing. Abort and Log probably shouldn't be offered.
6. **A used input can't be removed directly.** "Remove" is disabled with "clear those first", so you hunt down every use yourself. A "remove and leave holes" option would match how adding works.
7. **Recursion with a typed palette.** A hole whose type is `a` (a new `main`, an added value) offers 184 to 195 entries, starting with `for each`. Typing narrows it, but there's no "print" or "most likely" ordering for an action.

## UX issues (ranked)

1. **The graph gets too little room.** On a first visit at 1280×720 the Guide is open by default and the graph is about 120 px tall, so `fall` is drawn at roughly a third of its size (`first-visit-1280x720.png`). Even with the Guide closed, the Text pane is about as tall as the graph. Each graph is fitted down to 30 to 50%. The `main` graphs (96 nodes in Numbers & physics) are unreadable at Fit (`main-unreadable.png`). Ideas: close the Guide by default after the first visit or show it as an overlay, give the graph two thirds of the center, and Fit to a minimum readable zoom, then scroll.
2. **The Run panel is below the fold.** In the side column, Definition (pin, inputs, comment) comes first and Run is under it. Run-backwards answers need a scroll, and port names are truncated (`leading coeffici…`, `run-panel.png`). When you tick a port, the answer it produces isn't visible.
3. **Most functions open in a warning state.** 38 of 55 definitions have no example inputs, so they open with an orange "Give x a value, or untick it" and no values on the wires (queens, cubic, magnitude, greet…). The first impression reads as an error. Examples could be seeded from how `main` calls the function, or the hint could be neutral rather than orange.
4. **There's no way to deselect.** Clicking empty graph space starts a pan and Escape only closes menus, so a selection sticks. The definition inspector (inputs, pin, delete) comes back only after clicking the definition in the navigator again.
5. **New things land off-screen.** "Add a value here…" near the right edge puts the hole at the click and the dot 110 px further right, outside the view (`add-value-offscreen.png`). "Show inline" grows the graph past the right edge with no refit (`inline-overflows.png`).
6. **Wires run through labels.** Many wires cross the parameter names on a frame's left edge (`polar`, `root`). In `rotate`, the inner `(length) =>` and `(angle) =>` headers overlap each other. A let node's label sits on its wires.
7. **Tabs pile up.** Every definition opened from the navigator becomes a tab. After eight, the strip squeezes the graph hint into an ellipsis, and tabs are inserted after the current one, so their order stops matching the navigator. Consider replacing the current tab unless it was pinned or edited.
8. **"100%" reads like a zoom readout.** It's a button, and the real zoom level isn't shown anywhere. A plain mouse wheel zooms, so scrolling on a trackpad zooms too.
9. **A program opens on its first definition, not on `main`.** In Calculus, `main` is the 14th of 21 rows.
10. **Palette search doesn't match what's drawn.** The graph shows `√` and `·`, but searching `√` finds nothing (it's `sqrt`). A typed expression like `1 + 2` isn't understood, only plain values.
11. **Clearing a node generalizes the type.** Clearing `√` in `period` changes its type to `(a, b) -> Number`, the inputs show type `a` in the palette, and the units vanish. The hole itself says it needs Number.
12. **The type line breaks inside the arrow.** `(Number, Number, Number, Number) -` / `> Bool` in the inspector header.
13. **Keyboard.** Nodes, ports and Blocks items aren't focusable, and Tab skips the program entirely. Every edit needs a mouse.
14. **Phone width (390 px).** The panes stack into a 2,600 px page. The graph is fitted into the bottom-left corner of its pane rather than centered (`phone-390.png`). Right-click, shift and alt gestures have no touch equivalent.
15. **A new program starts in an error colour.** New program: `main : () -> a`, and the Run panel already shows "Values stopped: reached a hole" in orange before anything was asked.

## Suggested order

Following the step-by-step rule, one PR each:

1. B1: confirm, or make delete undoable.
2. B2: let a new input reach `solve` calls.
3. B3 and B8: solver and run messages.
4. B4.
5. UX 1 and 2: graph size and where Run sits. These change the most for a first-time user.
6. UX 4: deselect.
7. B5.
8. B6.
9. UX 5.
10. The "can't edit" list: start with inner lambda parameters and swapping a call's function. Those two block real programs most.

## How to repeat

The scripts drive the built page through `playwright-core`, the same setup as `editor/smoke.ts` (`CHROMIUM=/opt/pw-browsers/chromium`). They select by the editor's own attributes: `[data-def]`, `[data-act]`, `[data-menu]`, `.p-graph [data-edge]`, `[data-src]`, `circle.inp`, `[data-move]`, `.side .port-row`. Run `npm run smoke` before trying any finding above, and remember that a stale `localStorage` copy can make an example behave differently (see NOTES.md).
