# Editor click-through QA, 2026-11-22 (b)

This pass checks five editor PRs merged on 11-22 by pointing and clicking:

- **#2984 (E287):** each name set is edited in its own field.
- **#2989 (E288):** a node's comment sits in one box, as tall as its text.
- **#2993 (E289):** Blocks lay out too-wide lines indented.
- **#2995 (E290):** a Layout menu in Blocks (One line, Indented, Hide, Auto); calls nested more than 3 deep show as `…`; Fit and All.
- **#2996 (E291):** a node's comment shows as a line above it, in Blocks and in the graph.

It follows [QA-2026-11-22.md](QA-2026-11-22.md).

**Build tested:** `main` at `52db702` (#3024) plus #3026 (not merged), built with `npm run build-editor` in `ters/`. It was served over http through a playwright route that reads files from the repo (`file://` hides timing problems), and opened in headless Chromium at 1500 × 1000 and 1100 × 1000.

Screenshots are in [screenshots/2026-11-22b/](screenshots/2026-11-22b/).

## What works

- **Name fields (E287).** Picking `safe` in Eight queens shows two fields: Descriptive name first (the shown set), then Short name. A descriptive name typed there is saved to names.descriptive.json ("Renamed. Only names.descriptive.json changed"). Descriptive shows it, and Short names still shows `safe` (`name-fields.png`).
- **Comment box (E288).** It grows with its text: 71 px tall for up to three lines, 129 px for six. Tab saves it ("Comment saved on the node itself, not on a line").
- **Comment line above (E291).** In Blocks, each line of the comment shows as a `--` line above the node's line. In the graph, the first line shows in grey above the node, and the whole comment on hover (`comment-box.png`, `comment-in-graph.png`).
- **Layout menu (E290).** Right-clicking a call offers One line, Indented and Hide. Indented lays it out one input a line ("Indented. Only the layout changed."), and its comment stays above it (`layout-indented.png`). Hide on an indented part works since #3014.
- **Depth (E290).** With the editor's depth of 3, 213 of 2,074 example definitions show at least one hidden part as `…`, such as `cons(…, …)` in Page: bounce's `first impact`. None throws. All shows every part, and Fit hides them again.
- **No page errors** came up in the whole pass.

## Findings

| # | Finding | Repro | Severity |
|---|---|---|---|
| M1 | **Blocks lines run past the pane's edge when the pane is narrow.** E289 indents a line that's wider than a fixed width in characters, not the pane's width. With a page program at 1100 px wide, the page preview takes the right half and Blocks is about 280 px wide. Lines then run past its edge: Page: bounce's `picture` by up to 210 px and its `main` by 160 px, and Lockstep's `main` by 253 px. At 1500 px, calc (21 definitions) has none, and sheet (90) has one line 3 px over (`bounce-narrow-blocks.png`). | Window 1100 px wide → Page: bounce → `picture` | Medium |
| L1 | **Two kinds of `…` look the same.** A long text cut short in the pane (`"Credits: A* is Hart, Nilsson an…"`) and a hidden part (`cons(…, …)`) both read `…`, but only the hidden part opens when clicked. A text holding only a line break reads `"…" · 2 lines` (calc's `main`, `split(‹read input›(), "…" · 2 lines)`). The text shortening is older than E290; the clash is new. | Page: agent → `credits`; calc → `main` | Low |
| L2 | **A node's comment in the graph sits under the wires running into it.** In ledger's `run`, the two wires from `path` into `show ledger` cross the grey "shows the totals" line. | ledger → `run` → pick `show ledger` in Blocks → write a comment | Low |
| L3 | **A comment on a node inside a folded frame shows nowhere in the graph** until the frame is opened, and the folded box doesn't say it holds one. Blocks show it. | Eight queens → `safe` → comment `abs(queen − column)` | Low |
| L4 | **ledger's saved layout keeps places from before E295.** `show ledger` and its step were placed by hand when an unnamed step was drawn as a let's dot. They now sit far below, with the `0` it gives up and to the right. Tidy puts them back. | ledger → `run`, `usage` | Low (fixed in #3026) |

Not checked this time:

- Touch (the long press that opens the Layout menu on iOS).
- The Layout menu inside the graph, which doesn't offer it.

## Suggested order

1. M1: measure "too wide" against the Blocks pane's width.
2. L1: make a hidden part's `…` look different from a shortened text.
3. L4: clear ledger's stale places, or Tidy the examples' saved layouts.
4. L2 and L3.

## How to repeat

As in [QA-2026-11-22.md](QA-2026-11-22.md). Wait for `[data-def]` after clicking a program. The Layout menu's items are `.ctx-item` with `data-menu="shape-line"`, `"shape-lines"`, `"shape-hidden"` and `"shape-auto"`. The comment box is `#f-comment`, and the name fields are `#f-name` (the shown set) and `#f-name-<set>`.
