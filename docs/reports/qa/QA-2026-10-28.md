Screenshots are in [qa/2026-10-28/](screenshots/2026-10-28/).

## What works

- **Every example runs.** All 15 programs and 155 definitions were opened, and every `main` ran with its expected output. No page or console error came up, apart from Chromium's "Failed to create WebGPU Context Provider" warning, which is expected without a GPU. `SWEEP=all npm run smoke` passes (155 definitions, plus 16 on programs saved by an older editor).
- **A `main` opens on its steps** (#506). The numbered step column with its dashed order line is in the first view (`first-visit-1280x720.png`).
- **Interfaces from the editor.** New definition → Interface → `Size` makes `interface Size a` with one operation. Its panel edits the operation's Takes and Gives and lists implementations. Implement for Float64 makes `size at float64 : Size Float64` with a hole for the operation (`new-interface.png`, `implement.png`).
- **Make it a function** (#536). On `speed · time` in `fall`, it makes `part = (speed₂, time₂) => speed₂ · time₂`, and `drift = part(speed, time)`. The status says what happened, and one Undo puts it back (`make-it-a-function.png`).
- **Wrap in…** on `0.5` with `sqrt` gives `√0.5`: "Wrapped it in the call: it is one of its inputs."
- **Let and get nodes** (#546). In `fall`, `drift =` and `drop =` are let nodes with their values, and each use is a get node (`fall-let-nodes.png`).
- **Add a value before this** on a `main` step, filled with `print("hello")`, prints `hello` first when `main` runs, in Insertion sort and Numbers & physics. See M1 for how it reads.
- **The Mandelbrot picture** zooms, in the HSI colours, with credits for both above it (`mandelbrot.png`).
- **On a phone** (390×844) the page fits with no scroll (`phone-390.png`).

| H1 | **Opening Countdown's `solutions` freezes the page for about 20 seconds.** A requestAnimationFrame loop measured a 19.9 s gap between frames: no clicks, no scrolling, nothing redraws. Then Run shows `numbers target result []` with "Still looking for other answers…" and Stop (`countdown-solutions.png`). `main` calls `solutions(numbers, 765)`. Since #507, a definition's Run starts with what `main` first passes it, so opening `solutions` runs Hutton's whole search for 765 on the page's own thread. `Run main` runs the same search in a worker with Stop (#294), and that path is fine. Opening `join` takes 0.9 s. No earlier pass found a slow definition. Either run the opening values in the worker, or bound them as `main`'s trace is bounded (50 ms) and show "Run it" when they run out. | Countdown numbers → `solutions`. | High: the page hangs |

## How to repeat

As in [QA-2026-10-24.md](QA-2026-10-24.md) and [QA-2026-10-27.md](QA-2026-10-27.md). New this time:

- **Slow opens:** time each `[data-def]` click and flag any over 800 ms. Run a `requestAnimationFrame` gap recorder before clicking, and read its maximum after.
- **New definition → Interface** has Name and First operation. The interface's panel has Implement, with a select of types.
- **Run's palette and Run panel** are both `.side`. Read them together with `evaluateAll` over `.side`.
