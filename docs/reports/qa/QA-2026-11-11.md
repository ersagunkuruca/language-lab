# Editor click-through QA, 2026-11-11

The point-and-click pass after a batch of editor changes. It follows [QA-2026-11-10.md](QA-2026-11-10.md). Since then, 208 PRs landed, and ten of them touched the editor:

- **Calculus's `newton` opens with main's values again** (I196, #2185). This fixes the last report's L1.
- **Opening a definition is lighter.** Tooltip types read the checker once (I192d, #2278), and the graph's layout finds each unit's inputs once (I192e, #2294).
- **The long run is cut into pieces.** It stops at the opened definition's value (I189f, #2298), and its first drawing is a piece too (I189h, #2369).
- **Checks are kept between visits.** The first draw leaves the library's bodies to the worker (#2344). Checks are kept in IndexedDB (#2346), and Run's worker reads them (#2386).
- **The dividers fixed:** loose bounds, and dragging works over a page (#2351).
- **A one-port use read by two inputs keeps its dot** (I201, #2350).
- **Run main's check for running is about twice as fast** (I203, #2373 to #2382). That work is outside editor/, but it is what Run main waits on.

**Build tested:** `main` at `08807d9` (#2386), built with `npm run build-editor` in `ters/`, served with `python3 -m http.server` from the repo root, and opened in headless Chromium (playwright). There's no GPU here. The full browser smoke wasn't run, following Ersagun's note of 2026-10-29.

## What works

- **All 34 programs open, and so does every definition in them (1,220 opens).** No page error came up, and no console error other than Chromium's WebGPU warning.
- **Every one of the 21 text `main`s runs and gives its expected output.** Each run took 1.1 to 1.3 s from the click to the answer, and each said "Ran compiled".
- **All 13 pages, shaders and the board show their previews.** The dice, Pig, Tumble, outline, converter, pedal, constructions, bounce, spacetime and board pages each draw their text. The three shaders each draw a canvas.
- **`newton` (11-10's L1) is fixed.** It opens with main's call and reaches 1.324718.
- **The definitions the last report found slow now open quickly.** Each was opened alone after its program, three seconds after the program opened:

| machine `all digits` | 0.99 s | 0.43 s | 0.24 s |
| break `shifted` | 1.1 s | 0.27 s | 0.12 s |
| Spacetime `rapidity picture` | 1.2 s | 0.54 s, in the walk | not measured |

## Findings

| # | Finding | Repro | Severity |
|---|---|---|---|
| L1 | **Spacetime `scalar part` and `pseudoscalar part` open with an empty Run,** showing "Give m a value, or untick it to solve for it" (`spacetime-scalar-part.png`). It is the same on 11-10's build (`2175821`), so this isn't a regression. main never passes these two a value directly, only inside the views it draws, so no seed reaches them. The long run is told to stop once the opened definition has its value (I189f), and because that value never comes, it spends its whole budget. That is why one open in three still takes three tasks of about 0.4 s in a row (click to frame 1.4 s). The other two opens take 0.56 s. `rapidity` and `speed of` are seeded. | Spacetime → `scalar part`. | Low (I205) |
| L2 | **The ray marcher's `shadow` opens in 1.0 s** (tasks of 0.35 and 0.51 s). Without a GPU its picture is drawn on the CPU through WebAssembly, so it may be quicker on a real machine. | Shader: ray marching → `shadow`. | Low: headless only, as on 11-10 |

## Suggested order

1. L1: seed `scalar part` from the value its first caller gives it in main's run. Failing that, let the long run stop when the opened definition isn't reached. This is one PR, with a test.
2. L2: no work unless a machine with a GPU shows it.

## How to repeat

As in [QA-2026-11-05.md](QA-2026-11-05.md): run `npm ci` and `npm run build-editor` in `ters/`, serve the repo root with `python3 -m http.server`, and load playwright from `ters/node_modules`. The walk clicks each `.nav-row[data-set="program"]`, then each `.nav-row[data-def]`. It times click to rAF+setTimeout, presses "Run main" where there is one, and reads `.side`. It collects `pageerror` and console errors.
