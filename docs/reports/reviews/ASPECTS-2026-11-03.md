# What a good language needs, and what Ters has (2026-11-03)

Ersagun asked (2026-11-03): "Can you ask an unprimed agent (with no context
history of this session at all) for which aspects should a good programming
language have? Let it give a huge list, then we subtract what we have from
that."

**How.** A fresh agent with no project context, no memory and no tools was
asked only "what aspects should a good programming language, together with
its ecosystem, have?". Its answer, 315 items in 25 areas, is
[ASPECTS-UNPRIMED-2026-11-03.md](ASPECTS-UNPRIMED-2026-11-03.md), committed
unchanged before the repo was read (the first commit of this PR). Then each
item was checked against `main` at 5345b26: README, BACKLOG.md, LANGUAGE.md,
LIBRARY.md, the design notes, and the two reviews of the same morning
([FOUNDATIONS](FOUNDATIONS-2026-11-03.md), [BLIND-SPOTS](BLIND-SPOTS-2026-11-03.md)).

**Marks.**
**have**: built and documented.
**partial**: some of it is built; the note says what's left.
**planned**: an open BACKLOG row covers it (named).
**missing**: nothing built, no row.
**n/a**: not relevant to our goals, or ruled out by a design decision (named).

Our goals, as the coordinator put them: a serious language for programs,
shaders, websites, mobile and audio; simplicity; uniformity; effects as the
base.

## The count

| mark | items |
|---|---|
| have | 123 |
| partial | 77 |
| planned | 30 |
| missing | 24 (7 of them get a new row below) |
| n/a | 61 |
| **total** | **315** |

The list is a mainstream textual language's checklist, so many of its items
dissolve here rather than go missing: there is no text, so no grammar,
formatter, whitespace rules, typos or syntax errors; names are a side table,
so namespacing and renames are free; Int is unbounded, so overflow exploits
are gone; values never change and nothing is shared mutably, so data races,
memory models and locks have nothing to act on. Those are marked n/a with
the reason, or **have** where the property is the point (no null, no data
races).
