## What the bare question changed

Without our area names, the agent did **not** give "effects" an area of
its own: effect tracking shows up only as item 120 ("result types or checked
effects") and item 173 ("taint tracking or effect tracking, optional,
advanced"). It also left out audio and shaders except in a generic
"GPU programming, if in scope". So the first prompt did tilt the list
toward our goals, as Ersagun suspected. The rest of the list overlaps the
first run heavily.

New things this run raised that the first didn't:

- **Design philosophy as its own group** (1 to 15): a stated purpose,
  conceptual integrity, willingness to leave things out, a model you can
  hold in your head. Ters is strong here (README goals, the uniformity
  rule, FOUNDATIONS' "what not to change").
- **Control flow** (110 to 118): loops, labelled break, early return.
  Mostly n/a: there are no statements, and folds and recursion take their
  place.
- **Typestate and linear types** (80): ruled out in favour of effects
  (LANGUAGE.md's error table); the effect version is L192.
- **Union and intersection types** (74): missing, and no program has
  asked for them; data types with cases cover the common use.
- **Source maps for compiled targets** (269): a stop inside compiled code
  can't be traced back to the node it came from. **New row C141.**
- **Diff-friendly programs** (37): BLIND-SPOTS §13 noted it with no row.
  This is the second independent list to raise it, so it's ranked below.
- **Honesty about trade-offs** (296): have; every doc says how much of
  it is built.
