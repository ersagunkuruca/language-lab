# Sixth review: the language and its library

Written 2026-11-02 (early morning UTC) at `94d550d` (after PR #1028), a
critical review of the language and the standard library, asked for by the
coordinator to refill the Language lane during Ersagun's "as many tasks as
you can" run. It follows [REVIEW-2026-11-01b.md](REVIEW-2026-11-01b.md)
(R5) and works the same way: every library definition's type was printed
and read side by side, the docs were checked against them, and the holes
below were found with small probe programs written with the DSL, each run
in the evaluator and compiled to JavaScript. Nothing is fixed in this PR:
each finding has a repro here and a row in BACKLOG.md (L149 to L159),
ranked bugs first.

**What was looked at:** tonight's language merges (L137 to L148: tuples
at higher-order calls, any of inside any of, the simulated clock, Pair as
Tuple2, Int positions, recursion through map, flatten and padding), the
types of all 167 prelude, vectors and html definitions and the std
builtins, effects and `together`, numbers and `show`, text, LIBRARY.md,
TUTORIAL.md and LANGUAGE.md.

## The verdict, first

The core holds up. In every probe the evaluator and compiled JavaScript
printed the same thing. Tuples now work where R5 found them refused, and
L146's new termination rule could not be fooled (§ "Checked and fine").
The problems are at the library's surface, where the one-system idea has
not reached yet:

1. **`together`, `race` and `within` run only actions that do nothing but
   wait.** A branch's type is `() -[Await]-> a`, closed, so a branch can't
   print, fetch, read a file or draw a random number. The world's only
   ticket is a timer. So "runs several actions side by side" holds for
   timers alone, and Promise.all of fetches, the prior art the docs cite,
   can't be written. §1.
2. **L140 left some counts as Float64.** `count`, a Clifford grade, a
   blade's index list and `show decimals`' digits are all counts, and
   `count(…) + 1` at Int is refused. §2.
3. **Text is not Ordered.** `smaller("b", "a")` is refused although `sort`
   and `compare` order text, and four Text-only comparisons repeat
   `< ≤ > ≥`. §3.

## 1. `together` runs only waiting actions

The prelude's `together` (prelude-source.ts, L71b) runs each action under a
handler of Await and parks its rest as a `Branch`, whose `resume` field is
declared in std.ts as `() -[Await]-> Branch r`. A data type's field has a
fixed row, so the action's row is fixed too:

```
together : (List (() -[Await]-> a)) -[Diverge, Await]-> List a
race     : (List (() -[Await]-> a)) -[Diverge, Await]-> a
within   : (Float64, () -[Await]-> a) -[Diverge, Await]-> Optional a
```

**Repro:**

```
main() = together([() => print("a"), () => print("b")])
  error: together performs Console, which nothing here handles
```

The same happens for any branch that logs, reads a cell, uses Random under
`seeded`, aborts, or fetches. ANSWERED-LATER.md's own example ("a fetch's
ticket gives a Text, a timer's a Unit, in the same `together`") can't be
written either, for a second reason: `fetch text` is
`(Text) -[Network, Abort]-> Text`. It blocks and gives no ticket, and the
only operation that gives a ticket is `start timer`.

**Fix, in two rows.** L149: let the branches carry the caller's effects.
One way is a row parameter on a data type, so that `Branch r e` has
`resume : () -[Await, e]-> Branch r e`. That is the one type-system piece
missing, and Koka has it. The other way is for `together`
to keep its parked rests in closures it never stores in a typed field. The
first way is cleaner and also unblocks user code that stores effectful
callbacks in records. Probes for the row: two branches that print, in
order, under `simulated`; a branch that aborts, under `attempt`. L150: world
operations that start something and give a `Ticket` (`start fetch(url) :
Ticket Text`, then `start read file`). `fetch text` becomes
`await(start fetch(url))`, so its meaning stays the same.

## 2. Counts still Float64

L140 made positions and lengths Int. Some counts were left behind:

| definition | type now | should be |
|---|---|---|
| `count` (std) | `(() -[Choice]-> a) -> Float64` | `-> Int` |
| `clifford grade` | `(Algebra a, Float64, a) -> a` | grade `Int` |
| `clifford part`, `clifford with part` | blade as `List Float64` | `List Int` |
| `show decimals` | `(Float64, Float64) -> Text` | digits `Int` |

**Repro:** `count(() => one of([1, 2])) + 1` at Int: "add needs Int here,
got Float64". A plain literal still adapts, so `clifford grade(alg, 1, x)`
checks. A computed Int does not, for example a grade taken from
`length(blade)`. Times (`within`, `start timer`, `wait`) and seeds stay
Float64: they're measures, not counts. Row **L151**, P2. The examples that
use `count` need checking after.

## 3. Text is not Ordered

The prelude's `at most`, `more than`, `at least`, `smaller`, `larger`,
`minimum` and `maximum` work on any `Ordered` type. Text has no `Ordered`
implementation, so:

```
smaller("b", "a")
  error: smaller works only on a Number with < (Int, Rational, Fixed or Float64)
```

At the same time, `sort`, `compare`, maps and sets order text
alphabetically, and the prelude has four Text-only copies of the
comparisons: `comes before` (std), `not after`, `comes after` and
`not before` (L33). The error message also says "a Number", although
Ordered is open to any type.

**Fix.** `ordered(comes before)` for Text in the prelude, as Rational's is
written. Then the three prelude copies become the generic ones, their ids
read as the generic ones' (RENAMED_IDS, as L139 did), and the message says
"a type with <". Row **L152**, P2 (removing a special case).

## 4. The generic `show` prints internals

L74 says number types show as numbers, inside lists and records too. Two of
them don't:

```
show(as fixed(3))            → fixed(12884901888)     (show fixed gives 3)
show(maximum([3]))           → finite(3)
show(minimum([]))            → plus infinity
```

The first prints the raw count of 2⁻³² steps. The others print the
constructor names, where the editor (L125d, #865) shows 3 and +∞. Row
**L153**, P2: Fixed and Extended join the number types `show` knows.
Fixed's digits are `show fixed`'s, and Extended shows its number, or
`∞` / `−∞`.

## 5. `show` turns small Float64s into 0

`show` for Float64 (std.ts) rounds to 9 decimals:
`Math.round(x * 1e9) / 1e9`. So:

```
show(1e-12)   → "0"
show(123456.000000000123) → "123456"
```

The first is a nonzero number written as one that reads back as zero. The
editor's literal and a test's expected text then disagree with the value.
The generic `show` does the same. The rounding hides `0.1 + 0.2` as `0.3`,
which is what `equal`'s tolerance does too, but it costs every number below
1e-9 (physics constants, probabilities, gradients). **Fix:** the shortest
text that reads back as the same Float64 (JavaScript's `String(x)`, Steele
and White / Ryu as prior art), so `0.1 + 0.2` shows as
`0.30000000000000004`. Alternatively, keep the 9 decimals for numbers whose
size is above 1e-6 and switch to the shortest round trip below it. This is
Ersagun's call, since the first changes what every example prints. Row
**L154**, P2, with a decision.

## 6. No one ÷, and per-type copies of generic operations

NUMBERS.md promises "one `+ − · −x <` (and later `÷`)". The ÷ is still six
definitions: `divide` (Float64), `divide fractions`, `divide complex`,
`divide duals`, `divide fixed` and Algebraic's `divide`, plus Int's
`quotient`, which is a different operation. Each has the same type shape,
`(a, a) -[Choice]-> a`. A generic `smaller(a, b) / 2` can't be written over
every number type, and a program on its own `Arithmetic T` can't divide.
**Fix:** a generic `divide` resolved per type as `+` is (arith.ts), through
a `Field` interface (or a fifth Arithmetic field, absent for Int), with
Choice at zero. Row **L155**, P2.

Beside it, generic operations exist but their copies stay offered:
`show fraction`, `show complex`, `show dual` and `show fixed` beside `show`
(they print the same, except §4's Fixed), and `fraction as float64` and
`fixed as float64` beside `as float64` (Int's and Algebraic's are already
one overloaded name). Row **L156**, P3: the copies keep their ids for
saved programs and leave the palette, and the conversions become one name.

## 7. Docs that are wrong now

- **TUTORIAL.md §3.6 and §3.7** teach `Pair`, `fst(□)` and `snd(□)`, and
  list `Pair a b` among the standard types. Since L139 these are `Tuple2`,
  `first` and `second`, written `(a, b)`.
- **LIBRARY.md, `divide`**: "dividing by 0 gives infinity". Since L125 it
  has no answer (its own type says Choice). The text is in notes.ts,
  `builtin.div`.
- **LIBRARY.md, Trig**: `log : (a) -> a where a has Trig`, but Trig's `log`
  field has Choice. `h(x) = log(x)` is typed `(a) -[Choice]-> a`.
  reference.ts builds an interface operation's type with an empty row
  (`eff: { effs: [], tail: null }`), so every effect on an interface field
  is dropped from the reference.
- std.ts's header comment still lists Pair among std's data types.

Row **L157**, P2, size S. reference.test.ts guards LIBRARY.md against
notes.ts, but not notes.ts against the types.

## 8. `keep`'s test row is closed

```
keep : (List a, (a) -[Choice]-> Bool) -> List a
map  : (List a, (a) -[e]-> b) -[e]-> List b
```

`all`, `first` and `count` take the caller's row minus the world (std.ts
`searchRow`), so a search may draw from `seeded`'s Random or read a cell.
`keep` runs its test under a Choice too, but closes the row, so a test that
does anything besides choosing is refused. Row **L158**, P3: `keep` gets
`searchRow`'s shape.

## 9. A lazy stream's message

```
type Stream = node(next: () -> Stream)
make(u) = node(() => make(u))
  type make : (a) -> Stream
  error: make might not finish, and it is used where only a function that surely finishes fits
```

`make` itself finishes: what may not is the lambda inside, stored in a
field that wants a function that finishes. So the message names the wrong
thing. Writing the field as `() -[Diverge]-> Stream` works today. Guarded
corecursion, which would accept the first version, is NUMBERS.md stage 5
and stays later. Row **L159**, P3: the message names the lambda and the
field, and suggests Diverge on the field.

## 10. L147 is half there

GAPS round 7 SL2 says "`range` is Float64". std has two: `builtin.range`
(Float64) and `builtin.int.range`, which is Int, has a note, and is what
`repeated` and the fraction digits use. What sheet hit is the name: which
`range` a typed `range(n)` resolves to, and whether the palette offers the
Int one. The row is reworded to say so, so the lane starts from the right
question.

## Checked and fine

- **Tuples at higher-order calls (L137):** `apply(f, p) = f(p)` given
  `times`, `map` of a two-input lambda over a list of tuples, a two-input
  lambda passed where one input is called, `curry`/`flip` of `·` and `−`.
  All type and give the same answers in both engines.
- **Tuples as data:** sorted by parts in order, equal by value, map keys,
  nested show `(1, ("a", []), 3)`. `sort by` is stable on ties.
- **L146's termination rule** (size-change through `map`): four tries to
  fool it all stay Diverge. They are recursion through `map` on the whole
  input instead of a piece, through `keep`'s test, through a user's
  higher-order function that calls f on its whole input, and through a
  lambda that conses onto the item.
- **Partial operations (L125b):** `log 0`, `sqrt −1`, `1 / 0`, `0 ^ −1`,
  `(−8) ^ (1/3)`, `mod(5, 0)` and Int `power(2, −1)` give no answer, and a
  default takes over, evaluated and compiled. Int's `quotient` and
  `remainder` floor (−7, 2 → −4, 1), as documented.
- **Edges:** `take(xs, −1)`, `drop(xs, 9)`, `item at(xs, −1, d)`,
  `replace at` past the end, `slice` out of range, `split("", ",")` and
  `as map` with a repeated key (the last one wins) all give sensible
  answers. `sort` and `as set` refuse functions with a clear message.
- **Text:** `length` counts code points (`"😀é"` is 2). `characters`
  splits a combining accent from its letter (`e` + `́`), which is
  documented as per code point. `uppercase("straße")` keeps ß.
