## The verdict, first

The week built what R10 asked for. The library is no longer type-checked
for every program (R10 §2, I193, closed by #2365). A compile no longer
re-runs the checker after its rewrites (I203), and Run main's check is
about twice as fast. The R10 §2 test passes.

What it cost is that **more is now trusted, and less is watched**:

1. **A compiled gallery example crashes on load, and nobody has noticed
   for 42 hours.** `ters compile examples/backwards` writes a module that
   throws `ReferenceError: f5057927$mode0 is not defined` before printing
   anything. Bisect: C42a (#2160, 2026-11-10 03:10). The test that would
   catch it, examples-agree, runs in full only in the Nightly, and the
   Nightly hasn't finished in twelve nights. §1.
2. **Carried types are trusted with nothing checking them.** Three passes
   (hoist, withBodies and staging) now write the types of the nodes they
   make by their own rules: about 400 lines that restate infer's rules.
   No compile runs the verifier. It runs only in four test files. Two
   breakages of main came from carried types today (#2394, #2396). And
   for 4 of 48 examples, a carried compile writes different code from a
   rechecked one. §2.
3. **Three kept-check stores, each with its own key.** `.lab/` on disk,
   IndexedDB in the editor, and the per-group cache. Each key is one more
   place where a stale result could be read as current. They are all
   built with care, but nothing tests the keys against a change to the
   checker. §3.

## 1. A compiled example that crashes, and the Nightly that never finishes

```
$ ters compile examples/backwards -o b.mjs && node b.mjs
ReferenceError: f5057927$mode0 is not defined
    R2.branchesFrom(import.meta.url, { f5057927$mode0, f0, f1: f12, … })
```

`ters run examples/backwards` (the evaluator) prints its lines. The
compiled module lists a mode function in its worker table (C42a shares a
map's items on workers) that it never defines. `backwards` is the
relations example: `magnitudes to`, `who was greeted`, `cuts`. Its
directional modes are what `$mode0` names. The first bad commit is C42a
(#2160). The commit before it compiles and runs.

Why nobody saw it:
- A PR runs the typecheck only (CI cost rule).
- examples-agree runs "an eighth of the examples per change, all of them
  nightly" (compiler/test/examples-agree.test.ts).
- The **Nightly** has ended `cancelled` on every night from 10-31 to
  11-11, except one `failure` on 11-04. Its job has
  `timeout-minutes: 30`, and `affected.ts --all` takes longer. The `good`
  tag, which marks the last fully checked main, is still at `796f263`
  (2026-10-28).

So for two weeks no run has checked every example compiled, and the
review loop's "nightly catches what the slices skip" isn't true. R10 §3
found Check main in the same state, cancelled 38 runs of 40.

**Fix:**
1. Fix the mode function's emission for a shared map in a relation's
   mode, with a test that compiles and loads `backwards`.
2. Make the full sweep finish. Either split the Nightly into jobs that each
   fit 30 minutes (the suite is already file-sharded by affected.ts), or
   run the compiled-examples sweep alone, which is the part that finds
   crashes like this one. Ersagun's CI budget decides which.

## 2. Carried types: trusted, not verified

I203 (Ersagun: "while compiling no typecheck is needed") was planned as
"a compile reads the check's written-out typing (verify.ts elaborate)".
What was built is different: each pass that makes nodes writes their
types itself.
- hoist.ts: the hoisted lets.
- uses.ts `carried`: binders, parts, tuples, a filled use's function.
- stage.ts `typesMade` and `putBack`: residual nodes, lits, refs,
  lambdas, calls, rows by the nearest lambda.

That is about 400 lines of typing rules, written a second time outside
infer.ts. infer.ts's own rules are tested by every test. These are tested
by three test files (hoist, bodyless-use, stage), which elaborate and
verify one fixture each, plus one tamper.

**Evidence that it bites:**
- **#2394** (this lane, today). withBodies carried implementations the
  cut program no longer held. Five number tests (order, algebraic, fixed,
  one-divide, real) failed on main with "Cannot read properties of
  undefined". The covering tests had passed.
- **#2396** (Lane B, today). putBack skipped a call put back inside
  another put-back call's input, and `ters wasi examples/impact` failed
  on main.
- **The sweep above.** Of 48 examples, 44 compile to the same module with
  carried types as with the old rechecks. Four don't: backwards, calculus,
  conjugate and bounce. The differences are in the code the runtime
  solves with (`JSON.parse` of a relation's or derivative's code). In
  backwards, a filled use's call with `given` and `binds` stands where the
  rechecked compile has plain `cons` calls. All four print the same when
  run with no input, so this is not yet a wrong answer. But "carried
  equals rechecked" is not true, and each difference is a place where a
  pass decided differently on a different type.

**Why it matters more than a slow compile:** types decide code. hoist.ts
reads a function type's row to decide what may move (`own.eff.effs.length`).
The worker passes share only what is pure. A carried row that is too pure
moves or parallelises an effect. The verifier does check rows of
lambdas now, but no compile runs it.

**Fix (choose one, measure first):**
- (a) Run `verify` on each pass's output inside `ters compile`, if one
  pass over the nodes is as cheap as CHECKED-ONCE §3 A estimated. That
  estimate ("several times faster than inferring") was never measured;
  measure it first.
- (b) Or run carried against rechecked on every example in the sweep
  (the comparison above, as a test), so a pass that disagrees fails CI
  rather than main.
- And the four that differ: find what each pass decided differently, and
  either carry the type the check gives or write down why the
  difference is harmless.

## 3. Three stores of checks, three keys

| store | where | key |
|---|---|---|
| library check | `ters/.lab/` (library-store.ts) | library code + options + a hash of the checker's source files, found by following relative imports with a regex |
| editor checks | IndexedDB (editor/checkStore.ts) | `CHECKS_KEY` made by build.ts + what it was of, through a 53-bit cyrb53 hash |
| group checks | check-cache.ts, kept in both | the group's nodes + its callees' schemes + data types + options |

Each one has been thought through, and check-cache has a randomized
test. What no test does is change the checker and confirm every store
misses. library-store's import regex would miss a checker file reached
through a bare package import or a template string. Plus the three env
flags. Today added 794 lines to the check machinery (infer.ts, stage.ts,
uses.ts, verify.ts, library-store.ts, check-cache.ts, kept.ts), against
3,561 across ters/src and compiler/src.

None of this is wrong today. It is complexity creeping in on the one part
everything else trusts. **Fix:** one test that edits a checker file's text
in a temp copy and asserts every store misses. Then fold the three env
flags into one (`TERS_RECHECK=1`), since they are only ever used together
to compare.

## 4. `settled`'s claim (this lane's own, today)

`settled` reads the rate q off four rounds, then takes half way from it to
1. PageRank's first ratios are 0.51 to 0.71 and later ones reach 0.85, so
some margin is needed. But "half way" is a guess, chosen because it
passed that example. Its note says "q is an estimate", which is honest,
but:
- An answer from `settled` (not `settled by`) is not guaranteed within
  tolerance, and a reader skimming LIBRARY.md may read it that way.
- No answer means either "this step has no fixed point" or "the rate went
  over my guess". A program can't tell the two apart.

**Fix:** say in the note that only `settled by`'s answer is within
tolerance. Consider a third outcome in a later row (fall back to the
smaller bound). It isn't worth building until an example needs it.

## 5. Row ids collide

`I205` is three rows: the Spacetime empty Run (open), the number tests
(#2394), and impact on WASI (#2396). Across BACKLOG.md and DONE.md, 13 ids
appear twice: C140, C2, C201, C22, C6, E103q, I122, I205, I50, L11,
L193b, L214e5b2c, P4. Some of these are a row closed in two stages, which
is allowed. The I205s are lanes picking the same next number at the same
time. **Fix:** a lane takes a new bug id by adding the row to BACKLOG.md
in its first commit. Or, cheaper, a test that refuses a DONE id that
BACKLOG.md still has open.

## 6. The verifier's header, and termination

verify.ts says "effect rows … are the next steps". Rows of lambdas are
now checked: the test "a function whose row leaves out what a call in it
does is refused" passes. Termination is skipped (`skip("termination")`).
So `grow`'s and `settled`'s "never Diverge" come from infer.ts and
counting.ts alone. That is fine while the checker is trusted, but it is
not yet the "verify without trusting the checker" that CHECKED-ONCE
describes. **Fix:** correct the header, and list in CHECKED-ONCE what is
verified and what is still the checker's word.
