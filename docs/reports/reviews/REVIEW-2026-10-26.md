## The verdict, first

A lot landed: 425 commits since R2, about 28,000 lines. Every hole R2 could
put in a test is closed: all five of its todo tests pass. The project now
has generic arithmetic over Int, Number, fractions and complex numbers,
maps, sets, `compare` and `sort`, `Outcome`, mode analysis, operations
answered later, audio, and three new targets (WebAssembly with GC and WASI,
native C, an installable web app). The core held up under all of it, and
the effect ledger, the container matrix and the builtin records keep the
R2 class of bugs (an effect dropped by whatever consumes it) from coming
back.

Three things stand out now:

1. **Equality came back, in a worse place.** R2 settled on one rule for
   numbers: whole numbers are compared exactly, anything else within 1e-9.
   NOTES.md accepted that this isn't transitive. Since then, maps, sets and
   `sort` were built on `compare`, and `compare` uses the same rule. A
   sorted, duplicate-free container needs a total order, and this isn't
   one. A set of three Numbers has 2 or 1 items depending on the order they
   were added. NaN, which `0/0` and `sqrt(−1)` make in typed code, is
   "after" 1, and 1 is also "after" NaN. Separately, the "whole numbers are
   exact" half is decided by the float, not the type: `√2·√2 = 2` is true,
   and `√1e17·√1e17 = 1e17` is false. §1.
2. **Types with a rule have no way to keep it.** `Set`, `Map` and
   `Rational` are ordinary data whose constructors anyone can call, and the
   palette offers `set of`. `set of([3, 1, 3])` has size 3 and is not equal
   to the same set made properly; `ratio(2, 4)` is not equal to 1/2 though
   `compare` says it's the same; `ratio(1, 0)` exists. The language has no
   abstract types or private constructors, and the data structures plan
   (L61) depends on them. §2.
3. **The practices that catch drift fell behind the pace.** No
   click-through QA since 2026-10-24 midday, while about 65 editor PRs
   landed (E58 to E119), including loose parts, which changes how editing
   works. The last bigger program was the pedal (10-24). Sixteen debug
   scripts (`projectional/*.tmp.ts`) were committed in #332, and the two
   PRs R2 asked to close are still open. §4.

## 1. Equality and order on Numbers

### 1.1 Order-dependent sets

`compareValues` (run.ts) says two Numbers are "same" when `sameNumber`
says they're equal, and otherwise orders them by `<`. `sameNumber` is
within 1e-9 for anything not whole. So, with `a = 1000.5` and
`d = 1.5e-6`, `a` is the same as `a + d`, `a + d` the same as `a + 2d`,
and `a` is before `a + 2d`. `as set` keeps the list sorted with no item
twice, so:

| items, in this order | `set size` |
|---|---|
| a, a + d, a + 2d | 2 |
| a + d, a, a + 2d | 2 |
| a, a + 2d, a + d | 1 |

The same goes for `as map` with Number keys, and for which of two "same"
items `sort` keeps first. The weight-balanced tree (L76) is a second
representation of `Map`, chosen automatically by the chooser: with an
order that isn't one, the tree and the sorted list can disagree about what
a map holds. That last part wasn't run, it follows from the first.

NaN is reachable from total, typed code (`0/0`, `sqrt(−1)`, `mod(5, 0)`;
LANGUAGE.md's error table says Number's `/` is IEEE). Then
`compare(NaN, 1)` and `compare(1, NaN)` are both `after`; a set made from
`[NaN, 1]` doesn't contain NaN; a set made from `[NaN, NaN]` has two items;
`sort([3, NaN, 1, 2])` gives `[1, 2, NaN, 3]`.

NOTES.md "Equality: one rule" says the rule isn't transitive and accepts
it. That was a fair trade for `equal` as a wire in an equation. It is not a
fair trade for an order that a data structure relies on, and maps and sets
arrived after the trade was made (L65, L66, L76).

**Fix.** Give the order its own rule: `compare` on Numbers is exact and
total (IEEE 754's totalOrder, so −0 before 0 and NaN at one end), which is
what sorting and keys need. `equal` keeps its tolerance for equations.
Then a map's keys are exact, and `equal` of two maps or sets compares their
entries one by one, with the tolerance, which is what the user asked for
when they wrote `equal`. Say in LANGUAGE.md that keys are exact. The todo
tests R3 §1.2 and §1.3 check the order and NaN.

### 1.2 The tolerance vanishes for big Numbers

`sameNumber` compares two numbers exactly when both are whole. It has to
decide from the value, because an Int and a Number that happen to be the
same float look alike at run time. But at 1e17 every float is whole, so
the tolerance that NOTES.md introduced for the solver ("√2 squared is
2.0000000000000004") is gone there. `√1e17 · √1e17` is
`1.0000000000000002e17`, a whole float, so `equal(√1e17·√1e17, 1e17)` is
false while `equal(√2·√2, 2)` is true. Any equation over large quantities
(distances in metres, money in small units, the physics example scaled up)
loses the property the tolerance was there for, and a solver answer can
fail its own check.

**Fix.** The real cause is that a value doesn't know whether it is an Int.
Make it know: an Int is always a tagged value (or always a BigInt past
some bound and a branded number below it), so `sameNumber` can be "exact on
Ints, near on Numbers" from the value itself, with no type-directed
checker step (R2's objection) and no wholeness test. Todo test R3 §1.1.

## 2. Types with a rule can't keep it

`Set k` is `set of(List k)`, `Map k v` is `map of(List (Pair k v))`,
`Rational` is `ratio(Int, Int)`. Each comes with a rule the rest of the
library relies on: sorted with no key twice (DATA-STRUCTURES.md step 1),
lowest terms with a positive bottom (L39a). Nothing enforces it:

- `set size(set of([3, 1, 3]))` is 3, and `set of([3, 1])` is not equal to
  `as set([1, 3])`. The palette offers `set of` to fill a `Set` hole.
- `ratio(2, 4)` shows as 2/4 and is not equal to 1/2, while
  `compare(ratio(2, 4), 1/2)` is `same`. `ratio(1, 0)` exists, and it is
  `same` as `ratio(−7, 0)`. The palette doesn't offer `ratio`, but the
  checker accepts it, and so does any saved file.

This is the first missing language feature the data structures work
(L61, "meanings with representations") runs into. A meaning with a rule
needs its constructor to be private to the module that keeps the rule,
with smart constructors (`as set`, `fraction`) outside. The pieces exist:
modules and pins (signatures-modules) already decide what a module
exports. A variant marked private to its module, refused by the checker
elsewhere and left out of the palette, is the smallest change, and it
fits the uniformity rule (it's a flag on a variant, as `later` is). A
quotient type (equal by the rule rather than by spelling) is the bigger
alternative and isn't needed yet. Todo tests R3 §2.1 and §2.2: either
the checker refuses the raw constructor or the value obeys the rule.

## 3. Writing programs in the editor

R2's main worry was that no real program had been written in the editor.
That is much better: Countdown and ledger were built by clicks, a headless
browser driving the built page, and their GAPS sections list what the
editor made hard. The editor lane then worked through a long list of
gestures (E1 to E119). Loose parts (NODE-EDITOR.md, #433 to #436) change
the model: an edit can now leave a part unattached, kept in `drafts.json`
beside the program, rather than refusing anything that would break the
tree.

What isn't known yet:

- **Whether loose parts made programs easier to write.** No QA pass has
  run since they landed, and no program has been written with them.
- **The pedal was written with the TypeScript DSL**, not in the editor:
  `gen-pedal.tmp.ts`, committed by accident (§4), builds it with `Lang`
  and saves it. Its PR (#320) and GAPS round 4 don't say so, though GAPS
  says it for every other round. `generic` (#371) doesn't say either.
  The round with the most new language in it (conjugation, inverses,
  cells in a sound) is the one the editor never saw.
- **A person writing a program**, rather than a script that knows the
  answer in advance. The scripted builds prove every gesture exists; they
  don't measure how long a person takes to find it. The next bigger
  program should be written by the QA agent from a description of what it
  should do, with its stumbles recorded.

## 6. The four legs, and complexity

| leg | where it stands | weakest point |
|---|---|---|
| **Regular programs** | strong: JS, WebAssembly (WASI, no JS needed), native C; Int that never overflows on every target; maps, sets, sort, `Outcome`; a 2000-entry ledger | §1 and §2; no foreign function interface (L69 is a proposal), so nothing outside the built-in world |
| **Shaders** | WGSL with records as structs, Float32, Complex as `vec2f`, bounded loops only | no matrices yet (L44) |
| **Web** | one page model, time, randomness, HTTP, audio in a worklet, one-file output | the effects review's page oddities wait for L54's later steps (L59) |
| **Mobile** | `lab build-app`: an offline PWA that is also a Capacitor project | never run on a phone that we know of; no device APIs without an FFI |

**Is it on course?** Yes, with a caveat. The things a serious language needs
next are language features, not targets: abstract types (§2), a foreign
function interface (L69), concurrency on answered-later operations (L71),
and an order you can build data structures on (§1). Meanwhile the targets
grew: four code generators (JS, WASM, C, WGSL) and hand-kept runtimes in
WAT (`wasm-rt.ts`, 5,600 lines) and C beside the generated maths. Every
language feature from here has to be done four times. The builtin records
(L7) and the scalar lowering keep that manageable for numbers, but data
structures (L61) and concurrency will each touch all four. Ersagun's call
on 2026-10-24 ("the language comes first", BACKLOG lane C) is the right
one; this review only notes that the cost of each language feature is now
about four times what it was when the call was made.
