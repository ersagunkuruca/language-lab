# Using Ters through its MCP server, as an LLM (2026-11-01)

I (Claude) used the Ters MCP server (`lab mcp`, [MCP.md](../design/tools/MCP.md))
on a copy of Tumble, with only what the tools answer: look around, add a
function, give a match different cases, evaluate things. What went well,
and what got in the way. Fixed ones are marked; the rest are Inbox rows
I113 to I118 in BACKLOG.md.

## What works well

- **The view reads like code.** It is the editor's blocks text, so `fall`
  and `cascade` read at a glance, and `name#id` where each name is bound is
  enough to point at things. I never needed an id for a use of a name.
- **Short ids.** Four characters nearly always; I copied them from the
  gutter without thinking about them.
- **Diffs as answers.** A `define` answers `‹holes left›#u6gt(board#ma00) = □#9evp`:
  the next thing to fill, by id, in the answer. No re-view needed.
- **Refusals are safe.** A replace that adds a type error is refused with
  the checker's message and the file is untouched; `undo` covers the rest.
- **`eval` is the feedback loop.** `holes left(board([[-1, 1], [2, -1]]))`
  `= 2 : Int` after each edit, with no test file to write.
- **`find` by text.** Picking a part by the text the view shows
  (`find: "total(board)"`) is what an LLM does best; ids alone would mean
  a view per edit.

## What got in the way

| # | friction | status |
|---|---|---|
| 1 | After `split` on a Moment, all five cases are the same copy, so the view folds them into one `otherwise` and the cases can't be seen or reached | fixed in #856: `otherwise is: …` under the match, `replace … case:` |
| 2 | No way to find where something is used (`range(6)` is in 19 places) | fixed in #856: `search` |
| 3 | A field read prints as `board.columns` but can't be written back: `flatten(board.columns)` is "unexpected text at 8". Workaround: split on the record and use the field's name | I113 |
| 4 | `if c then a else b` prints but can't be written, nor a match or a let. Workaround: `step` a Bool, then `split` on it. Two steps and a refusal for the commonest thing | I114 |
| 5 | The reader's errors don't say what's wrong: a misspelt or missing function (`filter`) gives "unexpected text at 7" or "no case named if settled at 11" | I115 |
| 6 | A new function's inputs are generic until the body fixes their type, so `split` on one is refused ("that variable's type has no cases") until something like `total(board)` is put in first, only to be replaced | I116 |
| 7 | Splitting on a value whose cases have no fields gives copies that fold into one otherwise; in the editor an edit to it is made in every copy (`sameEverywhere`), so a person may have no way to give one case its own body. Not checked in a browser | I117 |
| 8 | A wrong argument blames the wrong place: `nth(s, row, "x")` says "this function needs List Text here, got List Float64", about the list, not the `"x"` | I118 |
| 9 | Tumble writes its size as `range(6)` in 19 places; making the board 7 wide is 19 edits. A program issue, not the server's; noted for the next bigger-program round | — |

## Choices made, for later

- Edits are saved as they are made (as a file-editing tool does), with
  `undo` for one step back. No separate save.
- Program output comes back in the answer; a page comes back as its text,
  not its HTML and CSS (Tumble's is 20 KB).
- `view` with no depth shows as much as fits 40 lines; Tumble's longest,
  `clear`, opens fully at that size.
