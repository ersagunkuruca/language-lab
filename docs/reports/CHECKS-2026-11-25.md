# Checks the program doesn't need, by kind (C331, native)

C331 asks what each kind of check costs across the suite, not at one
site. Here every check of one kind is dropped by hand from the C that
`ters native` prints. That is unsound, so each number is an upper bound.
The kinds are measured on eight `compiler/gaps` programs, nine runs in
all (mnist twice, reverse and Adam), on one thread. WebAssembly and core
JS are left for part 2.

## How

`ters native` on main at #3324 (with LAB_INLINE, #3322). The edit
scripts were run on the printed C, then `gcc -O2` with the flags
`ters native` uses:

- **ints**: tagged Int `+ - * < =` without the small test or the overflow
  check (`a + b - 1` on the tagged words).
- **bounds**: the index and empty checks in the array runtime (`item at`,
  `first`).
- **floats**: the Float64 guards that fail or stop (`x == 0` before a
  division, `x <= 0` before a root or log). C has no other finite checks
  (L258).
- **divs**: the zero test in Int `quotient` and `remainder`.
- **status**: every read of `lab_st` after a call (a try round each call).

Instructions are callgrind's count at the smaller size. Time is the best
of five at the larger size. Times move by about ±5% from run to run, so
the instruction counts are the measure below 10% (WORKFLOW.md "Measure
small gains with instructions"). "DIFF" means the program printed
something else without the checks: it uses that failure as control flow,
so the kind can't be dropped there, even as an upper bound.

|---|---|---|---|---|---|
| flock (30 2000; 100 5000) | 4.1% / 4% | 1.7% / 2% | 0.0% | 0.0% | 4.1% / 7% |
| scan (400; 1600) | 3.3% / 6% | none | none | 0.0% | DIFF |
| strings (8; 10) | 1.3% / noise | 0.3% | 0.0% | 0.0% | DIFF |
| pack (12800; 51200) | **20.7%** / 1% | 2.8% | none | 1.1% | 1.5% |
| mini (2000; 8000) | 1.1% / 1% | none | none | 0.0% | DIFF |
| typeset (1000 300; 4000 300) | 8.2% / 7% | DIFF | 0.0% | 0.0% | DIFF |
| bazaar (10000; 40000) | 2.9% / noise | 0.3% | 0.0% | 0.3% | DIFF |
| mnist reverse (200; 1000) | 1.6% / 2% | **14.5% / 12%** | 0.0% / 3% | 0.4% | -0.2% |
| mnist Adam (200; 1000) | 2.2% / 6% | **13.8% / 11%** | 0.1% | 0.5% | -4.9% |
| geometric mean (instructions) | **5.2%** | **4.4%** | 0.0% | 0.3% | n/a |

## What clears the bar

- **Array bounds** clear it on one benchmark: mnist, 14% of its
  instructions and 11–12% of its time. That is the 77 M `item at` reads
  per 1000 digits that the Language lane found (C333). They are `dot`'s reads, an index stepping by
  a stride for n rounds, so the range can be checked once on entry and
  the loop run unchecked (loop versioning). Row **C336**.
- **Tagged Int arithmetic** clears it by kind: 5.2% of the instructions
  across the suite, and pack alone 21%. The time gain is smaller (pack
  1%, typeset 7%), since the small test predicts well. C333 part 2
  untagged the counters of loops and recursions. What's left are Ints
  that aren't counters: sums, codes, positions read from data. Row
  **C337**.
- **Float64 guards** (0.0%), **Int division by zero** (0.3%) and the
  **failure reads after calls** don't clear it. The failure reads are
  needed by five of the nine runs and are mixed where they can be
  dropped (flock 4%, mnist -5%). They go in the cut log.

## C336, built

checked-once.ts checks `dot`'s and `strided sum`'s walks once as they
start (loop versioning). mnist natively, median of seven runs: reverse 384
-> 344 ms (10%), Adam 187 -> 159 ms (15%), the same output. Instructions
fell 9%: under the 14% that dropping every bounds check gave, since
`dot back` (a recursion, not a loop) keeps its checks. Its time fell more
than its instructions: the copy reads with no branch between the loads
and the sum. Kept out of line, since put into its caller gcc held the sum
in memory and the run was 16% slower than with the checks.

## WebAssembly

`ters wasi` under Node. The kinds were dropped in the runtime's own
functions (wasm-rt.ts, a scratch edit not kept): **ints** is `int.add`,
`int.sub` and `int.less` without the big Int test or the overflow test,
and **bounds** is `array.at` without its index check. Time is the median of
seven interleaved runs. V8 moves these by about ±8% (mini's bounds build
was byte for byte its base build and timed 8% faster), so only larger
numbers count.

| program | ints | bounds |
|---|---|---|
| flock (100 5000) | 0% | 7% |
| strings (10) | 2% | -13% (noise) |
| pack (51200) | 1% | 0% |
| mini (8000) | 6% | none (same build) |
| typeset (4000 300) | -4% | DIFF |
| bazaar (40000) | -4% | 3% |
| mnist reverse (1000) | -2% | 4% |
| mnist Adam (1000) | 0% | **12%; again, nine runs: 1036 -> 903 ms, 13%** |

Bounds clear the bar again on mnist (Adam 13%): C336's walks checked once
on WebAssembly too, row **C336b**. Tagged Int checks don't (about 0% across
the suite: V8 predicts the small test, and a wasm Int is a reference
either way), so they go in the cut log for WebAssembly.

## Core JS

The module `ters compile` prints, under Node, each kind dropped by an edit
script on the module (scratch `jdrop.py`), median of seven interleaved
runs. **ints**: std's Int `add`, `sub` and `mul` without the small test
on their answer (Numbers stay Numbers, BigInts go as before; dropping the
type test too breaks seven of nine runs, a BigInt meeting a Number).
**bounds**: the index and empty throws in `array.at`, `array.get` and
`array.first`. **floats**: the finite guards before a stop (`x - x ===
0`, 103 of them in mnist). **status**: `R2.ck`'s test for a failure.

| program | ints | bounds | floats | status |
|---|---|---|---|---|
| flock (100 5000) | -1% | -1% | 0% | 0% |
| scan (1600) | 6% | 3% | none | 0% |
| strings (10) | 0% | 1% | 2% | 1% |
| pack (51200) | 6% | -4% | 0% | -2% |
| mini (8000) | 4% | -3% | none | 0% |
| typeset (4000 300) | **10%** | -1% | 2% | 0% |
| bazaar (40000) | 0% | 3% | 3% | 0% |
| mnist reverse (1000) | 2% | -4% | -8% | -5% |
| mnist Adam (1000) | 5% | -2% | -5% | -3% |

Tagged Int checks reach the bar by kind on JavaScript too: about 3.5%
geometric mean, typeset 10%. That is close to the noise, so C337 measures
it again by instructions before building there. Bounds, finite guards and
failure reads buy nothing on V8 (cut log). Of the four, only bounds on mnist
cleared the bar on C and WebAssembly but not on JS: V8 hoists or predicts
that check itself.
